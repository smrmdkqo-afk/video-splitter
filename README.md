# Video Splitter

여러 영상을 **한 파일씩 순서대로**, **재압축 없이** 나누는 한국어 웹 앱입니다. 영상은 서버에 업로드하지 않고 브라우저 안에서 처리합니다. GitHub Pages에 올릴 수 있는 정적 사이트입니다.

## 사용 방법

1. MP4 · MOV · M4V 영상을 여러 개 선택하거나 끌어 놓습니다.
2. 파일별 재생시간, 예상 조각 수, 구간, 파일명을 확인합니다.
3. **순차 분할 시작**을 누릅니다. 한 원본의 처리가 끝나면 다음 원본으로 넘어갑니다.
4. 완료된 조각의 **저장** 버튼을 눌러 다운로드합니다. `저장 요청됨`은 브라우저에 다운로드를 요청했다는 뜻이며, 완료 여부는 브라우저 다운로드 목록에서 확인합니다.

처리 중 화면을 열어두세요. 다른 앱으로 전환하거나 기기를 잠그면 브라우저가 작업을 멈출 수 있습니다. 페이지를 다시 열면 이전 임시 결과는 정리되므로 먼저 저장하세요. 원본 파일은 변경하지 않습니다.

## 분할 규칙

- 기준: **250 MB = 250,000,000 bytes**. 조각 수는 `ceil(원본 용량 / 250 MB)`입니다.
- 전체 재생시간을 조각 수로 균등하게 나눕니다. 예: 900 MB · 20분 영상 → 약 5분씩 4개.
- 파일명: `여행.mp4` → `여행_1of4.mp4` … `여행_4of4.mp4`. 한글, 공백, 이름 중간의 점을 유지합니다.
- 250 MB 이하는 나누지 않고 원본 파일과 원래 이름을 그대로 제공합니다.
- 재압축하지 않으므로 실제 자르는 지점은 가까운 독립 재생 기준 프레임(키프레임)으로 조정됩니다.
- **250 MB는 용량 상한이 아닙니다.** 시간 기준으로만 나누므로 구간별 실제 용량은 달라지며, 300 MB를 넘으면 경고합니다. 용량에 맞춰 다시 쪼개거나 재압축하지 않습니다. 공유 앱의 실제 제한은 별도로 확인하세요.
- 완료된 조각에는 실제 재생시간과 용량을 표시합니다. AAC 오디오 프레임 경계·초기화 구간 때문에 길이가 계획과 소폭 다를 수 있습니다.

## 지원 범위와 한계

- 브라우저: HTTPS 또는 localhost에서 사용하는 최신 Chrome/Edge, Safari 등 **Web Workers, OPFS, Web Locks** 지원 브라우저. 기기·브라우저별 큰 파일 다운로드 동작과 임시 저장 한도는 다릅니다.
- 입력: 영상 트랙이 하나인 MP4/MOV/M4V. H.264 및 HEVC, AAC 조합을 실제 생성 영상으로 검증했습니다. 무음 영상, 복수 오디오 트랙, 회전 메타데이터, 가변 프레임 속도도 검증합니다.
- 출력: 독립적으로 재생 가능한 MP4. 원래 압축된 영상·오디오 패킷을 복사하고 시간표만 다시 구성합니다. 해상도, 화질, 오디오 패킷, 회전 정보는 유지하며, 새 영상 인코딩은 하지 않습니다.
- **지원하지 않는 코덱, 여러 영상 트랙, 부족한 키프레임, 이전 구간을 참조하는 열린 GOP 경계**는 오류를 안내하고 중단합니다. 소리를 버리거나 품질을 바꾸는 우회 처리를 하지 않습니다.
- 자막·챕터·카메라 전용 메타데이터를 보존하는 범용 편집기는 아닙니다. 영상과 지원되는 오디오 트랙을 분할하는 도구입니다. 원본은 별도로 보관하세요.
- 임시 저장 공간은 완료된 결과가 쌓이는 만큼 필요합니다. 공간이 부족하면 남은 작업을 중단합니다. 저장한 완료 항목을 목록에서 정리하면 공간을 되찾을 수 있습니다.
- 같은 사이트의 여러 탭이 서로의 임시 결과를 지우지 않도록 분할 작업은 한 탭에서만 허용합니다.

## 로컬 실행

Node.js 24 이상이 필요합니다.

```sh
npm ci
npm run dev
```

```sh
npm test           # 분할 계획, 파일명, 큐, 취소, 임시 저장 테스트
npm run test:media # FFmpeg/ffprobe 필요. 자체 생성 영상으로 실제 분할 검증
npm run build     # TypeScript 검사 + dist/ 정적 빌드
npm run preview
```

테스트 영상은 `.test-media/`에 생성되며 Git에 포함하지 않습니다. 테스트에는 개인 영상을 사용하지 않습니다. 실제 브라우저·모바일 기기의 파일 선택/다운로드 동작은 별도의 기기 확인이 필요합니다.

## GitHub Pages 배포

`.github/workflows/pages.yml`이 `main` 변경 시 테스트·빌드를 실행하고 `dist/`를 Pages 아티팩트로 만듭니다. Pages가 GitHub Actions 방식으로 활성화되어 있으면 이어서 배포합니다. 활성화 전에는 테스트·빌드만 수행하고 **Check Pages setup**에 필요한 설정을 표시합니다. 이 워크플로는 저장소 공개 범위나 요금제를 변경하지 않습니다.

처음 한 번 필요한 관리자 설정:

1. [Settings → Pages](https://github.com/smrmdkqo-afk/video-splitter/settings/pages)에서 **Build and deployment → Source → GitHub Actions**를 선택합니다.
2. [Actions](https://github.com/smrmdkqo-afk/video-splitter/actions/workflows/pages.yml)에서 **Build and deploy Video Splitter → Run workflow**를 실행합니다.
3. `Deploy GitHub Pages` 작업이 성공하면 표시되는 배포 주소를 엽니다.

기본 예상 주소는 `https://smrmdkqo-afk.github.io/video-splitter/`이며, **배포가 성공하기 전에는 사용 가능한 주소가 아닙니다**. 실제 주소는 Pages 설정/배포 결과를 기준으로 확인합니다.

GitHub Free의 Pages는 공개 저장소를 대상으로 합니다. 이 저장소처럼 private을 유지하려면 개인 계정의 GitHub Pro 등 Pages를 지원하는 유료 요금제가 필요합니다. 저장소가 private이어도 일반 GitHub Pages 사이트는 공개 웹사이트이므로 민감한 파일을 빌드 산출물에 넣지 마세요. [GitHub 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## 구성

- TypeScript + Vite: 모바일 대응 UI와 정적 배포
- Mediabunny: 입력 메타데이터 확인, 키프레임 탐색, 압축된 패킷 복사, MP4 생성
- Web Worker: UI와 별도로 영상 처리
- OPFS + 2 MiB 청크 쓰기: 결과 전체를 메모리에 쌓지 않고 브라우저의 임시 저장소에 기록
- 서버, API 키, 외부 영상 업로드, 분석/광고 스크립트 없음

Mediabunny는 MPL-2.0 라이선스입니다. 수정하지 않은 배포본을 사용하며, 배포 사이트의 **오픈소스 안내**에서 라이선스와 원본 소스 위치를 확인할 수 있습니다.

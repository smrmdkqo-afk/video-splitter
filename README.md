# Video Splitter

여러 영상을 **한 파일씩 순서대로** 나누거나 해상도를 낮추는 한국어 웹 앱입니다. **분할만 할 때는 재압축하지 않고**, 해상도를 낮출 때만 영상을 다시 인코딩합니다. 영상은 서버에 업로드하지 않고 브라우저 안에서 처리합니다.

[웹 앱 열기](https://smrmdkqo-afk.github.io/video-splitter/) · v1.2.0

## 사용 방법

1. 처리 방식을 선택합니다. 기본값은 **분할만 · 원본 유지**입니다.
2. MP4 · MOV · M4V 영상을 여러 개 선택하거나 끌어 놓습니다.
3. 파일별 재생시간, 입력/출력 해상도와 예상 결과를 확인합니다.
4. **순차 처리 시작**을 누릅니다. 한 원본의 변환·분할이 모두 끝나면 다음 원본으로 넘어갑니다.
5. 완료된 결과의 **저장** 버튼을 눌러 다운로드합니다. `저장 요청됨`은 브라우저에 다운로드를 요청했다는 뜻이며, 완료 여부는 브라우저 다운로드 목록에서 확인합니다.

처리 중 화면을 열어두세요. 다른 앱으로 전환하거나 기기를 잠그면 브라우저가 작업을 멈출 수 있습니다. 페이지를 다시 열면 이전 임시 결과는 정리되므로 먼저 저장하세요. 원본 파일은 변경하지 않습니다.

## 홈 화면에 앱 설치

- 화면 오른쪽 위 버튼을 사용합니다. 브라우저가 설치창을 제공하면 **앱 설치**, 그렇지 않으면 **설치 방법**을 표시합니다. 지원 여부를 브라우저 이름으로 단정하지 않습니다.
- 설치 방법에는 Android/삼성 인터넷, iPhone·iPad, 컴퓨터별 안내와 주소 복사가 있습니다. 앱 내 브라우저에서는 주소를 복사해 Chrome·삼성 인터넷·Safari 등에서 여세요.
- 영상 정보 확인·변환·분할·정리 중에는 설치 버튼을 비활성화합니다. 설치창을 확인하는 동안에도 새 영상 작업을 시작하지 못하도록 합니다.
- 선택한 영상이나 임시 결과가 있으면 먼저 안내하고 확인을 받습니다. **저장 요청됨은 저장 완료가 아닙니다.** 다운로드 목록에서 완료를 확인한 다음 기존 탭을 닫고 설치한 앱을 여세요. 선택 목록과 임시 결과가 새 앱으로 자동 이전되지는 않습니다.
- 설치 수락만으로 완료 처리하지 않습니다. 브라우저의 설치 완료 이벤트가 오거나 설치된 앱 모드로 실행할 때 버튼을 숨깁니다. 설치창 취소·실패 뒤에도 수동 설치 안내를 제공합니다. 설치 여부를 영구 저장하지 않으므로 오래된 기록 때문에 버튼이 계속 사라지지 않습니다.
- 설치 기능은 원본·결과를 삭제하거나 페이지를 새로고침·이동하지 않습니다. 영상 처리 방식도 변경하지 않습니다.
- **서비스 워커와 오프라인 캐시는 추가하지 않았습니다.** 앱을 여는 데 인터넷 연결이 필요하며 설치해도 백그라운드 영상 처리를 보장하지 않습니다. 설치와 오프라인 기능은 별개입니다. [MDN 설치 안내](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)
- 앱 식별자는 `/video-splitter/`이며 시작 주소와 범위도 이 프로젝트 안으로 제한합니다. 다른 GitHub Pages 저장소 앱과 식별자가 겹치지 않습니다. 다른 저장소 이름으로 배포하면 manifest의 `id`도 변경하세요.

## 처리 방식과 해상도

| 처리 방식 | 결과 |
| --- | --- |
| 분할만 | 원본 해상도와 화질 그대로 시간 분할. 영상·소리 재인코딩 없음. |
| 해상도 변경만 | 선택한 최대 해상도로 축소하고, 분할 없이 하나의 파일로 저장. |
| 해상도 변경 후 분할 | 전체 영상을 한 번 변환한 다음 **실제 변환 용량**으로 조각 수를 계산하고 시간 분할. 두 번째 영상 인코딩 없음. |

- 출력 해상도: **1080p / 720p / 480p**. 가로 영상은 각각 최대 1920×1080 / 1280×720 / 854×480 범위에 맞추며 세로 영상은 최대 가로·세로를 바꿔 적용합니다.
- 화면 비율과 방향을 유지합니다. 잘라내거나 늘이지 않으며, 작은 원본은 확대하지 않고 변환도 건너뜁니다. H.264의 짝수 크기 제약으로 480p 16:9 출력은 852×480 등으로 조정될 수 있고 최대 2픽셀 안팎의 여백이 생길 수 있습니다.
- 실제 해상도 변경 시 영상은 H.264로 다시 인코딩합니다. 원래의 프레임 시간표(가변 프레임 속도 포함)를 유지하고, 모든 지원 오디오 트랙의 압축 데이터를 복사합니다. 회전 정보는 출력 픽셀에 반영합니다.
- 인코딩 비트레이트는 출력 픽셀 수·원본 프레임 속도·원본 비트레이트를 바탕으로 설정합니다. 화질과 파일 용량은 원본과 달라지며, **축소해도 용량이 반드시 줄어드는 것은 아닙니다.**
- 변환 전 용량·분할 개수는 확정할 수 없으므로 `변환 후 확정`으로 표시합니다. 변환 완료 후 실제 용량, 결과 수, 파일명과 시간 구간으로 갱신합니다.
- 해상도 변경만 한 결과는 `원래 이름.mp4`로 저장합니다. 변환 후 250MB 이하이면 분할하지 않고 그 변환 파일을 제공합니다. 작은 원본을 변환하지 않았다면 기존 확장자·이름도 그대로 유지합니다.
- 설정 변경은 새 영상과 대기·실패·중지 항목에만 적용합니다. 완료 항목은 유지하고, 부분 결과를 새로 만들거나 정리하기 전에는 확인을 받습니다.
- 진행률은 현재 변환/분할 단계와 전체 작업을 함께 표시합니다. 변환 후 분할 모드의 전체 진행률은 변환에 85%, 분할에 15%를 배정한 근사치이며, 남은 시간은 기기 성능·영상 내용에 따라 달라집니다.

## 분할 규칙

- 기준: **250 MB = 250,000,000 bytes**. 조각 수는 `ceil(분할 대상 파일 용량 / 250 MB)`입니다. 해상도 변경 후 분할은 **완성된 변환 파일**을 기준으로 합니다.
- 전체 재생시간을 조각 수로 균등하게 나눕니다. 예: 900 MB · 20분 영상 → 약 5분씩 4개.
- 파일명: `여행.mp4` → `여행_1of4.mp4` … `여행_4of4.mp4`. 한글, 공백, 이름 중간의 점을 유지합니다.
- 분할만 할 때 250 MB 이하는 원본 파일과 원래 이름을 그대로 제공합니다.
- 재압축하지 않으므로 실제 자르는 지점은 가까운 독립 재생 기준 프레임(키프레임)으로 조정됩니다.
- **250 MB는 용량 상한이 아닙니다.** 시간 기준으로만 나누므로 구간별 실제 용량은 달라지며, 300 MB를 넘으면 경고합니다. 용량에 맞춰 다시 쪼개거나 재압축하지 않습니다. 공유 앱의 실제 제한은 별도로 확인하세요.
- 완료된 조각에는 실제 재생시간과 용량을 표시합니다. AAC 오디오 프레임 경계·초기화 구간 때문에 길이가 계획과 소폭 다를 수 있습니다.

## 지원 범위와 한계

- 브라우저: HTTPS 또는 localhost에서 사용하는 **Web Workers, OPFS, Web Locks** 지원 브라우저. 기기·브라우저별 큰 파일 다운로드 동작과 임시 저장 한도는 다릅니다.
- 해상도 변경은 추가로 **WebCodecs 디코더·H.264 인코더와 프레임 변환 기능**이 필요합니다. 선택한 원본 코덱과 출력 크기의 지원 여부를 시작 전에 확인합니다. 지원하지 않으면 더 낮은 해상도, 다른 브라우저 또는 `분할만`을 안내합니다. 브라우저 이름만으로 모든 기기의 지원을 보장하지 않습니다.
- 입력: 영상 트랙이 하나인 MP4/MOV/M4V. H.264 및 HEVC, AAC 조합을 실제 생성 영상으로 검증했습니다. 무음 영상, 복수 오디오 트랙, 회전 메타데이터, 가변 프레임 속도도 검증합니다.
- 분할 출력: 독립적으로 재생 가능한 MP4. 분할 대상 파일의 압축된 영상·오디오 패킷을 복사하고 시간표만 다시 구성합니다. 분할 단계에서는 해상도·화질을 바꾸지 않고 영상 인코딩을 하지 않습니다.
- HDR·넓은 색역 영상의 색상/밝기를 보존하는 해상도 변경은 아직 지원하지 않으므로 변환 전에 거절합니다. `분할만`은 해당 원본 데이터를 유지합니다.
- **지원하지 않는 코덱, 여러 영상 트랙, 부족한 키프레임, 이전 구간을 참조하는 열린 GOP 경계**는 오류를 안내하고 중단합니다. 소리를 버리거나 품질을 바꾸는 우회 처리를 하지 않습니다.
- 자막·챕터·카메라 전용 메타데이터를 보존하는 범용 편집기는 아닙니다. 현재 미디어 라이브러리가 읽지 못하는 일부 MOV의 기존 언어 태그는 출력에서 `언어 미지정`이 될 수 있지만, 실제 오디오 데이터와 트랙 수는 유지합니다. 원본은 별도로 보관하세요.
- 임시 저장 공간은 완료된 결과가 쌓이는 만큼 필요합니다. 해상도 변경 후 분할 시에는 변환본과 생성 중인 조각이 함께 존재하므로 추가 공간이 필요합니다. 분할 종료·오류·중지 시 중간 변환본은 정리하고 완료된 조각은 유지합니다. 공간이 부족하면 남은 작업을 중단합니다. 저장한 완료 항목을 목록에서 정리하면 공간을 되찾을 수 있습니다.
- 해상도 변경은 단순 분할보다 느리고 배터리·메모리를 더 사용하며 발열이 있을 수 있습니다. 큰 파일은 여유 공간이 있는 기기에서 처리하세요.
- 같은 사이트의 여러 탭이 서로의 임시 결과를 지우지 않도록 분할 작업은 한 탭에서만 허용합니다.

## 로컬 실행

Node.js 24 이상이 필요합니다.

```sh
npm ci
npm run dev
```

```sh
npm test           # 분할/변환 계획, 파일명, 순차 처리, 취소, 임시 저장, 설치 상태·설정 테스트
npm run test:media # FFmpeg 6+ / ffprobe 필요. 자체 생성 영상으로 실제 분할 검증
npm run test:resize # 실제 리사이즈, 회전·VFR·소리 보존, 변환 후 분할·취소 검증
npm run build     # TypeScript 검사 + dist/ 정적 빌드
npm run preview
```

설치 아이콘 PNG(192/512px, maskable, Apple 180px)는 기존 분할 아이콘을 그대로 사용하며 저장소에 포함합니다. `npm run icons:generate`로 다시 생성할 수 있습니다. 이 스크립트는 Node 내장 모듈만 사용하고 네트워크나 외부 프로그램을 실행하지 않습니다. 일반 로컬 테스트·빌드에는 아이콘 재생성이 필요하지 않으며, GitHub Actions에서는 테스트 전에 아이콘을 다시 생성해 함께 검증합니다.

테스트 영상은 `.test-media/`에 생성되며 Git에 포함하지 않습니다. 테스트에는 개인 영상을 사용하지 않습니다. 리사이즈 통합 테스트만 Node용 `@mediabunny/server` 코덱 어댑터를 사용해 동일한 처리 코드를 검증합니다. 이 개발 의존성은 웹 앱에 포함되지 않으며 **서버를 실행하거나 영상을 업로드하지 않습니다.** 실제 브라우저·모바일 기기의 하드웨어 코덱, 파일 선택/다운로드 동작은 별도의 기기 확인이 필요합니다.

## GitHub Pages 배포

`.github/workflows/pages.yml`이 `main` 변경 시 아이콘 생성 → 단위 테스트 → 실제 영상 분할·해상도 변경 테스트 → TypeScript 검사·빌드 → 배포 파일 확인 순서로 실행하고 `dist/`를 Pages 아티팩트로 만듭니다. 어느 단계든 실패하면 새 버전은 배포하지 않습니다. Pages가 GitHub Actions 방식으로 활성화되어 있으면 검증 통과 후 배포합니다. 활성화 전에는 테스트·빌드만 수행하고 **Check Pages setup**에 필요한 설정을 표시합니다. 이 워크플로는 저장소 공개 범위나 요금제를 변경하지 않습니다. 배포 파일의 SHA-256도 작업 로그에 기록합니다.

처음 한 번 필요한 관리자 설정:

1. [Settings → Pages](https://github.com/smrmdkqo-afk/video-splitter/settings/pages)에서 **Build and deployment → Source → GitHub Actions**를 선택합니다.
2. [Actions](https://github.com/smrmdkqo-afk/video-splitter/actions/workflows/pages.yml)에서 **Build and deploy Video Splitter → Run workflow**를 실행합니다.
3. `Deploy GitHub Pages` 작업이 성공하면 표시되는 배포 주소를 엽니다.

현재 배포 주소는 [smrmdkqo-afk.github.io/video-splitter](https://smrmdkqo-afk.github.io/video-splitter/)입니다. 기존 GitHub Actions Pages 배포를 유지합니다.

배포 사이트는 공개 웹사이트입니다. 개인 영상·비밀 키·민감한 파일을 저장소나 빌드 산출물에 넣지 마세요. 이 앱은 선택한 영상을 업로드하지 않습니다.

## 구성

- TypeScript + Vite: 모바일 대응 UI와 정적 배포
- Mediabunny + WebCodecs: 입력 메타데이터 확인, 해상도 변경, 키프레임 탐색, 압축된 패킷 복사, MP4 생성
- Web Worker: UI와 별도로 영상 처리
- OPFS + 2 MiB 청크 쓰기: 결과 전체를 메모리에 쌓지 않고 브라우저의 임시 저장소에 기록
- 서버, API 키, 외부 영상 업로드, 분석/광고 스크립트 없음
